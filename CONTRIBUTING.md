# Contributing

Contributions should make the method easier to apply, safer to operate or simpler to verify.

## Before opening a pull request

1. Keep examples generic. Do not submit customer lists, private campaign copy, credentials or provider exports.
2. Add sourced facts only when the source URL, access date and claim qualifiers are present.
3. Keep the project provider-neutral. Provider-specific examples belong in `docs/IMPLEMENTATION.md`.
4. Run `npm test`.
5. Explain the user-facing change and the validation performed.

## Good contributions

- Stronger deterministic checks.
- Better intake questions.
- New compliance-floor examples with authoritative references.
- Provider-neutral implementation patterns.
- Accessibility and email-client compatibility improvements.

## Out of scope

- Scraped mailing lists.
- Cold-email evasion tactics.
- Fabricated testimonials or urgency.
- Claims that bypass the fact pack.
- Private production code copied without permission.
